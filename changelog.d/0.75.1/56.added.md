- **`training.l2l` accepts `task: dpo`, `orpo`, `simpo` and `kto` (#56).** With `stream_layers: true`, each streamed layer is loaded once per optimizer step and runs all k micro-batches for the four preference tasks, as it already did for `sft`. A window loss reproduces the TRL loss of each method, and DPO and KTO run their reference pass through the loaded layer, so L2L loads the same number of layers per step as L2L SFT. The default stays `false`. Only DPO passed the readiness rule (SmolLM2-135M, RTX 3060, 12 synthetic rows, bf16 judged with the `MATH` SDPA backend pinned at step 0); ORPO, SimPO and KTO run but did not pass and are untested. DPO refuses `dpo_beta_schedule`, `dpo_beta_end`, `neftune_alpha`, a `ref_model`, precomputed reference log-probabilities and a `loss_type` other than `sigmoid`; KTO refuses `neftune_alpha`, a `ref_model`, a `ref_adapter_name` and a `loss_type` other than `kto`. The loss of trl 0.29.0, the lower bound in `pyproject.toml`, was not checked; trl 0.29.1 was. The readiness table, the refusals and the limits are in `docs/performance-and-quantization.md`.

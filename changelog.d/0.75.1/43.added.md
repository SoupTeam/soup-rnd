- **`training.l2l` spills activations to disk instead of stopping when they do not fit RAM (#43).**
  The budget takes the smaller of free RAM and the smallest cgroup remainder over the process's
  cgroup chain (limit minus (use minus inactive file cache), `memory.high` counted on v2), and is
  the smaller of 0.7 of that and that less a 512 MiB reserve for the rest of the training step
  (the reserve decides below 1.79 GB). Pinned chunks are counted at their power-of-two size. The
  reserve is chosen, not measured: in one GPU run (Mistral-7B NF4, LoRA r 8, k 4, seq 512) the
  first step allocated about 183 MB outside the store after the budget was read, and the 0.7
  share alone left 130 MB and was OOM-killed. When the activations fit, nothing
  changes. When they do not, the lowest layers go to one unbuffered file, sized once for the
  largest window of the tokenized dataset, and one console line names the layers, the file, the
  budget and the level that limited it; each logged step carries `l2l_spill_layers`. The run
  still stops, with what to change, when even every layer spilled does not fit. New optional
  `training.l2l_spill_dir` (default `<output>/_l2l_spill`, only with `l2l: true`). RAM-backed,
  overlay and network filesystems, a drive without the file size plus max(1 GiB, 10%) free,
  and a volume where unbuffered I/O fails are refused; on the disk tier the default directory
  is refused on the weights' disk. The file is removed at a normal end, on an exception, on
  Ctrl-C and when the disk fills. In the earlier A4 v3 configuration (RTX 3090 on PCIe 3.0,
  Mistral-7B NF4, seq 512, k 2-4, ring 4, one virtual disk), measured slowdown averaged +2.5%
  and +1.7%, 95% upper bounds +6.1% and +5.5%; sharing the weights' drive made the step 13%
  slower there. Cleanup remains best-effort: after kill -9, an OOM kill, a power loss or an OS
  crash the file stays until the next run in the same directory removes it at start (if its
  process is gone), or by hand; its path is in the console line. The trainer path was checked
  end to end on CPU. GPU session 3 (RTX 4090 VM, Mistral-7B NF4, k 4, seq 512, 13 of 32
  layers spilled) matched no spill bit for bit, stayed within its cgroup limit, and passed
  normal-end, Ctrl-C-in-backward and kill -9/next-start cleanup. Cost was +2.39% per step
  (95% interval -1.80% to +6.57%, 5 blocks, cost B children spilling 12-18 layers): below 10%
  confirmed on this faster machine only. **L2L vs GA still FAILS criterion 1b**, the same
  four tolerance failures as session 2, cause unestablished; not a spill finding because
  spill equals no spill. Retained private tensors allowed byte-identical comparison replay;
  the rule verdict also replayed byte for byte. Session 1/2 NO VERDICT records are unchanged.
  [Protocol and session 3](../../benchmarks/a3-spill-gpu-check.md#11-session-3-rtx-4090-vm-2026-10-28-protocol-v3-spill-confirmed-1b-fail);
  [public evidence and provenance](../../benchmarks/results/a3-spill-v3-rtx4090-20261028/README.md).
  Post-measurement audit fixes bind stale cleanup to verified file objects during replacement
  races (POSIX preserves unsafe-to-restore captures at a logged recovery path, not auto-swept),
  map non-default cgroup mounts, classify macOS volume backing, block non-CUDA host transfers,
  cap unbuffered requests at aligned platform limits, and release old/partial stores safely.
  Cleanup is still best-effort if interruption occurs inside CPython's native thread-launch
  window before a worker identity is published. CUDA growth uses public pinned-cache release
  when available; older torch may conservatively
  refuse growth while that cache remains charged. These fixes have local CPU spill and cleanup
  checks, not a new GPU/MPS/macOS-volume or large Windows-transfer measurement. Stand validators
  now reject incomplete numerical/cleanup evidence and nonfinite admission timings, enforce
  cost-step counts and the session deadline, without changing historical verdicts or thresholds.

- **`training.l2l` spills activations to disk instead of stopping when they do not fit RAM (#43).**
  The budget is the smaller of free RAM and the smallest cgroup remainder over the process's
  cgroup chain (limit minus use minus inactive file cache, `memory.high` counted on v2), times
  0.7, with pinned chunks counted at their power-of-two size. When the activations fit, nothing
  changes. When they do not, the lowest layers go to one unbuffered file, sized once for the
  largest window of the tokenized dataset, and one console line names the layers, the file, the
  budget and the level that limited it; each logged step carries `l2l_spill_layers`. The run
  still stops, with what to change, when even every layer spilled does not fit. New optional
  `training.l2l_spill_dir` (default `<output>/_l2l_spill`, only with `l2l: true`). RAM-backed,
  overlay and network filesystems, a drive without the file size plus max(1 GiB, 10%) free,
  and a volume where unbuffered I/O fails are refused; on the disk tier the default directory
  is refused on the weights' disk. The file is removed at a normal end, on an exception, on
  Ctrl-C and when the disk fills. The slowdown was measured only in the A4 v3 configuration
  (RTX 3090 on PCIe 3.0, Mistral-7B NF4, seq 512, k 2-4, ring 4, one virtual disk): +2.5% and
  +1.7% on average, 95% upper bounds +6.1% and +5.5%. On other machines and configurations it
  may be more; with the spill on the weights' drive the step was 13% slower. Cleanup is
  best-effort: after kill -9, an OOM kill, a power loss or an OS crash the file stays until the
  next run in the same directory removes it at start (if its process is gone), or by hand; its
  path is in the console line. The trainer path was checked end to end on CPU only: its one
  GPU check (RTX 4090 VM) stopped with no verdict when the run, under a cgroup limit that made
  it spill 18 of 32 layers, was OOM-killed in its first step, so under a tight limit leave
  room beyond the 70% budget.

- **Layer streaming accepts DeepSeek-V3 (`model_type=deepseek_v3`) (#6).** The sharder stacks per-expert checkpoint keys into the fused experts transformers 5.19 builds, drops the MTP layer, and the runtime loads the router bias from the checkpoint and keeps it in fp32. A tiny synthetic model streams bit-exact against a resident one in fp32 on an RTX 3050 (and on CPU, except NF4, which needs a GPU), for forward, backward, NF4, the disk tier, LoRA on attention and `moe_lora` on the routed experts; NF4 leaves the routed experts at the base dtype. `trust_remote_code: true` is refused for DeepSeek-V3. A local folder whose `config.json` has `auto_map` (every DeepSeek-V3 download) no longer needs `--trust-remote-code` when its `model_type` has a built-in transformers class, because transformers ignores `auto_map` then. An unknown `model_type` still needs the flag. `soup export` for AWQ and GPTQ also still needs it when `tokenizer_config.json` names a Hub tokenizer. The architectures `deepseek_v32`, `deepseek_v2` and `kimi_k25` stay refused. No real DeepSeek-V3 checkpoint has been streamed. The compatibility table and raw logs are in `benchmarks/gate-b2-deepseek-v3.md`.

- `target_modules: auto` on a DeepSeek-V3-shaped model (`deepseek_v3`, `kimi_k2`, `kimi_k25`) with `q_lora_rank: null` now adapts the single `q_proj` instead of the absent `q_a_proj` and `q_b_proj`. Before, the query projection got no adapter. Models with a `q_lora_rank` (V3, R1, Kimi K2) resolve as before (#6).

- `moe_lora: true` on DeepSeek-V3 now adapts the MLA attention projections (`q_a_proj`, `q_b_proj`, `kv_a_proj_with_mqa`, `kv_b_proj`, `o_proj`) as well as the routed experts. It named `q_proj`, `k_proj`, `v_proj` and `o_proj` for every MoE model, so on DeepSeek-V3 only `o_proj` got an adapter. `deepseek_v4`, `glm_moe_dsa`, `kimi_k2` and `kimi_k25` now get their own attention names the same way. Architectures whose attention is `q_proj`, `k_proj`, `v_proj` and `o_proj`, and those without a table entry, keep their targets (#6).

- The layer-stream shard cache is rebuilt when the model's decoder layer count, expert stacking or fp32 keys differ from the cache's, not only the stacking. A cache written before the index recorded its fp32 keys is rebuilt for DeepSeek-V3 and reused for models with no fp32 keys. The sharder also decodes block-scaled FP8 expert weights before stacking them, which the real DeepSeek-V3 checkpoint layout needs (#6).

- LoRA on the shared experts of DeepSeek-V3 under layer streaming. `target_modules` that name `shared_experts` (a list such as `["shared_experts.gate_proj"]`, or a regex) now attach to the shared experts. Before, peft 0.21 moved `gate_proj`, `up_proj` and `down_proj` targets onto the fused routed experts without an error. The adapter-budget preflight sizes the same adapter, and `export`, `merge` and `serve` reload a saved shared-expert adapter onto the shared experts. The rewrite is skipped for that one config only; other adapters load through peft as before. The gate record lists the parity arms (#6).

- `training.moe_lora: true` together with `shared_experts` entries in `training.lora.target_modules` is now refused. `moe_lora` replaces `target_modules`, so the shared-expert targets used to vanish without an error. A shared-expert attach now also fails if peft puts an adapter on the routed experts the config did not ask for, and a saved adapter that mixes shared-expert names with a bare `gate_proj`, `up_proj` or `down_proj` is refused on reload (#6).

- Layer streaming accepts Kimi K2-Base and K2-Instruct (`model_type=kimi_k2`, block FP8) as an alias of `deepseek_v3`. transformers 5.19 does not know the type, so Soup reads the `config.json` into a `DeepseekV3Config` without Hub code and registers the per-expert to fused-expert conversion for `kimi_k2`. Without it a native load leaves every routed expert at its random init and a save writes fused keys. The sharder drops the per-layer `rotary_emb.inv_freq` keys K2 checkpoints carry. `--trust-remote-code` is refused for `kimi_k2`, Kimi-K2-Thinking (INT4) and `kimi_k25` stay refused, and the K2 tokenizer is not covered yet. A tiny `kimi_k2` checkpoint streams bit-exact against a resident one for forward, backward, NF4, the disk tier and LoRA on attention, shared experts and routed experts. No real K2 checkpoint has been streamed, and one real K2 MoE layer is about 17 GB, which needs sub-layer streaming (#6).

- `soup chat`, `soup infer`, `soup diff`, live eval, iterative DPO, MoLE routing (training and serve), the adapter merge in `soup shrink` and `soup draft`, CMA-ES merge scoring and the interference measurement now reload a saved DeepSeek-V3 shared-expert adapter onto the shared experts. They called plain `PeftModel.from_pretrained`, which attached it to the routed experts and changed logits by up to 0.63 on a tiny model. Adapters trained on the routed experts load as before (#6).

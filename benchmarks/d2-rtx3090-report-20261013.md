# D2 isolated dense projection timing — RTX 3090, 2026-10-13

Raw measurements, historical files and replay commands are preserved in the
[D2 evidence archive](d2-evidence-archive.md). Evidence links below pin the
pre-cleanup snapshot; use that checkout for the original replay paths.

**Valid scoped timing, mixed result: no consistent speedup across the matrix.**
QKV/MLP with input gradients have about 1.04x median PEFT/fast combined ratios;
the remaining regimes are about 0.95–0.99x, so some regress. All valid arms,
including the FP16 single/no-dX low cycle around 0.884x, are retained. This is
not an end-to-end training multiplier or full D2 completion.

## Scope and protocol

Hardware: RTX 3090, 24 GB, sm86, driver 595.71.05. Linux/Python 3.12.3;
torch 2.11.0+cu126, PEFT 0.20.0, Transformers 5.17.0, bitsandbytes 0.50.1,
Triton 3.6.0. Native BF16 CUDA preflight passed; a real Triton kernel compiled
and executed after timing finished. Exact packages and device records are retained.

Synthetic dense projection fixtures: hidden 4096, GQA KV 1024, intermediate
14336, rank 16, batch 1 / 128 tokens. Base **and adapter** weights use the
requested FP16/BF16 dtype; this is not the mixed FP32-adapter NF4 streaming case.
These are independent single/QKV/SwiGLU projection fixtures, not a complete
attention/decoder block or pretrained 8B model. Dropout is zero; no optimizer
or parameter updates are timed.

The [predeclared protocol](d2-isolated-timing-protocol.md) uses five ABBA cycles
per case, a fresh OS process/CUDA context per arm, at least 20 warmups/two seconds
of warming, and at least 100 event pairs/one second per arm. CPU-prefork only
shares imported CPU libraries; the parent masks CUDA during imports, never
initializes CUDA, and is checked before every fork and at exit. Each child
constructs its own model/context from the same case's frozen state and inputs.

The CPU NVML supervisor observes empty pre-context lists, one persistent NVML
PID after child initialization, and empty lists after child exit. Child PID and
GPU UUID are retained. Independent replay also checks all startup observations,
graphics peers, timing-interval telemetry, power state, throttle flags and the
5% within-arm/across-cycle clock rule. All **60/60 cycles / 240/240 arms** pass;
observed timed SM clocks are [1740] MHz, with zero within-cycle spread.
There are 42,542 raw synchronized forward/backward sample pairs.

## Numerical verification and provenance

Every measured arm's final output and all requested dX/dA/dB tensors pass the
unchanged criterion against the stored PEFT and float64 tensors; missing keys,
wrong dtype/shape and nonfinite values fail. The 12 same-shape correctness gates
and changed-adapter controls precede timing. The loop is deterministic with fixed
weights, inputs/upstream and no optimizer; the final sample is checked outside
CUDA event regions, not every raw timing pair individually.

Local Windows CPU replay independently confirms **1,640 comparisons / zero
failures**, matching Linux CPU replay exactly: **1,600 exact / 40 approximate**.
This finite dense matrix does not establish universal bit-exactness. The existing
v7 BF16/NF4/streaming correctness results remain separately scoped.

Final source ZIP SHA-256: `b74db5f940762d84e51b02741921d52679a0194b5bc83c125e0b5113b91c735c`.
All 1,431 snapshot files match the working source; Git line-ending normalization
may change stored bytes. The production autograd implementation is unchanged
from f32a73478b89edd92256127ed990817e10a35bc6.

The failed CDI host, short-warmup VOID pilot, interrupted slow-import v3 pilot,
and rejected CUDA-initialized CPU template are recorded. The final template
masks CUDA during CPU imports; the safety guard was not weakened. Original
v6/v7 VOID records remain VOID and are not retrospectively reclassified.

## CI and cleanup

Rerunning Windows/Python 3.10 on the old head completed with a native PyTorch
2.14.1 `0xc000001d` abort in BF16 Linear, rather than a numerical assertion.
The [failed job](https://github.com/SoupTeam/soup-rnd/actions/runs/38289340960/job/115209450876)
and its log are retained. The affected four CPU cases now use the repository's
existing `aten_half_matmuls` fixture, avoiding the known oneDNN/MKL CPU ISA route
while preserving BF16, assertions and all cases. All four pass locally; the 24
timing/audit/materializer tests pass and full source/scripts/tests/harness Ruff
is clean. Full CI must run on the new revision; local tests are not a waiver.

The ZIP has verified remote/download SHA-256 and CRCs; 3,144 included payloads
verify after lossless tensor deduplication is restored. Both task instances were
destroyed and API cleanup verified at 2026-10-13T09:44:04.7824310Z. The original
one-hour window was respected; observed additional team balance decrease is
$0.1469, below the $0.50 limit (not a final invoice).

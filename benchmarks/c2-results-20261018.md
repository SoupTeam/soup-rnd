# C2: two pending reads per physical drive — 2026-10-18

**Decision: keep shipped depth 1.** On the admitted single-NVMe Linux host,
the completed diagnostic primitive comparison found a median paired ratio of
1.0080, with every pair inside the preregistered 0.95–1.05 no-benefit band.
The accepted diagnostic step series found median paired speedup **1.025243**
(+2.524%). Both effects fail the frozen benefit thresholds: primitive all pairs
>=1.10; steps every pair >=1.05 and median >=1.10, plus the original mean rule.
This does not establish a useful acceleration. The strict quiet-disk hardware
gate remains unmet; the separate bounded-background-write study cannot
authorize production integration regardless of its effect.

The benchmark adapter changes pending layer admission from one to two while
keeping four range workers per root, three-layer read-ahead and the same staging
allocation. Production `src/` is unchanged. This is a measurement/report PR;
it does not enable a new default or claim C2's original hardware gate is closed.

## Retained failures and scope

Host A was rejected as RAID1; B's quiet-write checks voided both sequences;
C failed to start its NVIDIA container; D was deleted during the user's pause.
Their inventories, failed journals and cleanup receipts remain in
[`evidence/c2-linux-nvme-20261018/`](evidence/c2-linux-nvme-20261018/).
E's first strict idle read check and subsequent 180-second idle-only observation
are retained separately. No earlier host or void arm contributes to E's result.

Linux measurements do not establish Windows direct-I/O behavior. A single
physical drive does not establish striping or dispatcher behavior across two
physical disks. The original exclusive-window acceptance condition requires
an independent run; this report supplies a reproducible conditional comparison
and a conservative keep-depth-1 decision for review.

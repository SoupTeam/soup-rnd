# D1 RTX 3090 pilot, 2026-10-15

**Decision: retain the shipped native dispatch; do not enable the forced
Function for training from this pilot. D1 remains open.** The measured
checkpointed projection subset shows no time or peak-memory win. The real QA
screen gives identical endpoint metrics and adapter byte hashes, with no
observed advantage from forcing the Function. This is a bounded study of the
already shipped #842 implementation, not a new fused backward kernel.

## Numerical correctness

Both CUDA FP16 and BF16 passed the 32768x12288 nested-NF4 alias fixture and the
four-layer/two-slot streaming fixture in cohorts Initial and A. Each packed
alias weight is 201,326,592 bytes (192 MiB); a dense half weight is 768 MiB.
Checkpoint-visible recycled buffers match private buffers exactly; the
deliberately broken plain-ctx implementation produces finite, different dX.
Positive recomputation is observed twice and the broken control once.

At each dtype and M=3, all logits and 16 expected LoRA gradients match an
unpatched resident reference exactly. The streamed Function counter is 56,
resident matmul counter 28, streamed matmul counter zero. At M=2048 the
corresponding counters are 0/28/0 and the dense dispatch is observed. Nonzero
LoRA B prevents the gradient comparison from being vacuous.

The primary existing GPU regressions report **4 passed, 8 skipped, 17
deselected**. The eight #968 skips require bitsandbytes 0.50.2; they are not
presented as passes. Isolated cohort C with that version reports **12 passed,
zero skipped, 17 deselected**, and passes both half-precision correctness
fixtures. All six stored dtype/cohort fixtures replay on CPU: 216 exact
quantities and six detected broken controls. No RTX 3090 run verifies sm_120
behavior.

## Repeated projection results

BF16 nested NF4, N=K=4096, non-reentrant checkpoint, frozen base and input
gradient; no LoRA or optimizer. Each arm uses 5,000 warm-up steps and 100
synchronized timed steps. Values below are medians of the ten arm medians
per route across five valid ABBA blocks, not medians of a pooled step stream.
F1 requires zero additional blocks for its 10% effect-size sizing rule in
both cases. These descriptive ratios do not support a 1–4% win claim.

| M and routes | A median ms | B median ms | A/B | Allocated peak A/B | Reserved peak A/B |
|---|---:|---:|---:|---:|---:|
| 8: dense / native Function, fused forward | 2.029720 | 2.289118 | 0.886682 | 110,567,424 / same | 138,412,032 / same |
| 2048: native dense / forced Function, dense fallback | 3.188805 | 4.298535 | 0.741835 | 277,094,400 / same | 289,406,976 / same |

M=8 per-arm median ranges: A 1.751726–2.223608 ms, B 2.053783–2.470491 ms.
M=2048: A 3.138115–3.202665 ms, B 4.229179–4.321096 ms. The same-session
dense GEMM ceiling, CUDA event times and all telemetry are retained per arm.
Ceilings are measured after peak capture and do not represent full training.
Median dense forward GEMM ceilings are 0.161203 ms / 1.665201 TFLOP/s at M=8
and 0.993510 ms / 69.168353 TFLOP/s at M=2048. The projection clock ranges
are 1695–1695 and 1830–1890 MHz, respectively, with a constant 350 W limit.

The native/forced candidates are checked against unpatched bitsandbytes
output and dX. The explicitly dense M=8 baseline can differ from native fused
arithmetic; its numerical differences are retained rather than called exact.
At M=2048 the forced forward actually invokes the dense fallback. Calling this
case a fused training kernel would be incorrect.

The current backward still dequantizes a full dense weight. Equal measured
forward/backward peaks are consistent with that implementation. Extra
checkpoint/autograd work is a plausible explanation for the forced route's
timing, but this study does not attribute an overhead percentage without a
profiler. Do not extrapolate one 4096x4096 projection to the full shape grid.
CPU replay of all 56 projection arms also passes: 42 exact native comparisons,
and 14 explicitly retained dense/fused arithmetic differences. This does not
rehabilitate the earlier void timing records.

## Ablation, validity, evidence and remaining work

The baseline/nodequant ablation is synthetic-token timing on the pretrained
RAM-tier model at sequence 512. Nodequant substitutes cached **zero** dense
weights; its mathematics is garbage. Its ratio probes removable overhead and
is never an achieved numerical kernel speedup or task-quality result. All
cached-zero allocations count toward its peak. Final repeated values, accepted
blocks and sizing are recorded in the evidence index: five accepted blocks,
zero required top-up, baseline median 326.804895 ms and cached-zero median
280.024750 ms (A/B 1.167057). This is about a 14.3% reduction in this garbage
ablation, not an achieved correct-kernel gain. Allocated peaks are
546,899,456 / 602,473,984 bytes; reserved peaks are 702,545,920 / 721,420,288
bytes. Clock range 1935–1950 MHz, fixed 350 W limit; every validity and peer
check is clean. A zero-weight timing probe is not a mathematical guarantee
that a real fused implementation can recover the same difference.

Initial timing stays NO_VERDICT: UUID-prefix mismatch, overlay block-device
mapping, and out-of-containment shard placement were recorded. Amendment A
fixes UUID representation and temp placement and adds a conservative upper
bound on **all** visible block-device reads for that overlay condition. It
includes partitions, stacked devices and own reads, with no subtraction.
Original unknown rows remain in the evidence. This is not a per-volume,
cold-disk, network-filesystem or comprehensive host-isolation guarantee.
Amendment B's warm-up does not relax the 5% clock-spread threshold. The failed
first bundle transfer before cohort B also remains in the controller log;
no measured arm was started by that failed transport attempt.

The [evidence index and replay instructions](evidence/d1-rtx3090-20261015/README.md)
cover the full raw archive, records, numerical replay, package compatibility,
ablation and rental cleanup. Failed/void attempts are preserved. Exact
duplicate files use lossless tar hard links: 622 files / 2,109,230,258 logical
bytes become an 87,304,984-byte archive in 21 chunks of at most 4 MiB. Every
restored file's size and SHA-256 was checked. No oracle file is omitted.
Cloud credentials, private keys and the private teammate conversation are excluded.

The rental was destroyed after 4,414 seconds and its absence verified through
the authenticated instance list. The provider's post-destroy charge snapshot
is **$0.47** (GPU $0.393, disk $0.048, download $0.026, upload $0.003), within
the authorized $2 cap. This is the instance-specific reported charge, not a
settled final invoice or an account-balance inference.

Remaining acceptance work: the complete five-shape/six-M/two-dtype projection
grid, at least five valid real-task timing blocks with any required F1 top-up,
broader model/task coverage if claimed, and independent review of the recorded
evidence. CPU replay by this author is not that independent review. Focused
regressions and lint do not establish the full cross-platform CI matrix.
No production runtime change, issue closure, merge or package release is
justified by this bounded pilot alone.

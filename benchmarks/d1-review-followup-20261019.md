# D1: короткая проверка после review, 2026-10-19

**Позднейший результат:** [VM F1](d1-vm-f1-result-20261019.md) дал пять валидных
блоков, sizing_extra=0: меньше VRAM, медленнее полный шаг при1200 MHz.
Ниже — история предшествовавших попыток; их NO_VERDICT не изменён.

**Полная D1 остаётся открытой.** Changelog добавлен, пробелы покрытия перечислены
в [acceptance ledger](D1_ACCEPTANCE.md). Новый CUDA-прогон обнаружил ограничение
A100; нового валидного perf-результата нет. [Ранее проверенная экономия VRAM](d1-final-result-20261016.md)
157 MiB allocated / 140 MiB reserved на синтетическом Soup fixture сохраняет силу.
Положительное ускорение не является условием приёмки валидного сравнения.

## A100: корректность не прошла, timing не запускался

Vast A100 SXM4 40 GB, sm_80, driver595.91.07,
UUID `GPU-318db20d-d2e8-34ad-8be2-bec477f3eeb8`, lease56604017.
Torch2.11.0+cu126, bitsandbytes0.50.2, BF16 nested NF4, default reduced-precision
reduction включён. Выполненный source: `28b0b724e2475a82275bb8e66fb29ec28492d1ba`.

| Gate `(M,N,K)=(128,32768,12288)`, packed192 MiB | Результат |
|---|---|
| Forward vs native resident NF4 | exact, 0 различий |
| dX vs native resident NF4 | FAIL: 746429 различий, max abs 0.0625; значения конечны |
| Checkpoint после перезаписи packed weights/scales | Два вызова recompute |
| Plain-ctx отрицательный контроль в том же процессе | Конечное отличие обнаружено |
| Полный шаг / ABBA / скорость | NOT_RUN: остановка после correctness FAIL |

CPU replay исходных CUDA-тензоров независимо воспроизвёл числа и контроль;
SHA-256 witness и raw archive совпали. Все 610 файлов выполненного source archive
сверены с указанным Git commit (только известная CRLF/LF-нормализация при сравнении).
Сырые байты архива сохранены. Попытка lock SM была отклонена провайдером; это не
меняет численный FAIL и не заменяет его частотным объяснением.

Вывод: наблюдавшаяся на sm_86 BF16 split-K арифметика не переносится автоматически
на этот A100. A100 не добавлен к поддерживаемому scope. Ослабление exactness,
подмена эталона, глобальная смена BF16-настроек и timing после FAIL не выполнялись.
Нельзя из этой проверки делать вывод о скорости или всех остальных формах A100.

## RTX 3090: контейнер не запустился в короткое окно

Отдельный lease56606044, machine55636, новая аппаратная cohort. Тот же source
подготовлен для запуска по неизменному F1-правилу; неисполненный source не
выдаётся за исполненный. По истечении 10 минут состояние оставалось `loading`.
Аренда удалена; CUDA, parity и timing на этом lease **NOT_RUN**.

## Дополнительные RTX 3090 попытки: F1 остаётся NO_VERDICT

Следующая короткая сессия использовала неизменные F1-правило и kernel из source
`e274b7e2905574c0864b91a02dd8b390ba1bad6b`. Аппаратные cohort не объединялись.

| Попытка | Ресурс | Результат |
|---|---|---|
| 01 | RTX 3090, machine17662, lease56610875, фактический power limit420 W | Correctness PASS; первый ABBA-блок отклонён, SM1800–1950 MHz (>5%); остановка после четырёх arms |
| 02 | Запрос Linux VM | API отказал `no_ssh_key_for_vm`; team account не поддерживает регистрацию account SSH keys. Аренда не создана, CUDA NOT_RUN, account key не добавлен |
| 03 | RTX 3090, machine150023, lease56613719, фактический power limit350 W | Correctness PASS; общий SM1800–1935 MHz (>5%); внешний stop, 17 завершённых arms / 3400 timed steps; ноль принятых блоков |

В обеих выполненных cohort отдельно прошли forward/dX большого packed192 MiB
recycled-buffer gate, два checkpoint recompute и конечный отличающийся plain-ctx
отрицательный контроль. Три обновления против native streaming и отдельно
unpatched resident дали **204/204 точных конечных quantities**, по 16 ненулевых
градиентов в каждом обновлении. GPU regressions: **12 passed** на каждой cohort;
dispatch probe: candidate40, native_custom0. CPU audit сверил все 609 файлов
выполненного source и исходные CUDA witnesses; это проверка записанных данных,
а не новая GPU-проверка. Пробелы shapes/dtypes/GPU в ledger остаются открытыми.

Clock lock был запрещён на обеих RTX. В 03 до создания аренды записан одинаковый
для A/B запрос `CUDA_AUTO_BOOST=0`; он не является фиксацией частоты или доказанной
причиной изменения поведения. В первом блоке 03 разброс укладывался в 5%, позже
вышел за предел. Проверка использует весь primary/reference clock cohort, поэтому
даже первый блок не извлекается для отдельного положительного вердикта. Полная
телеметрия и same-session GEMM сохранены; отвергнутые времена не используются
для количественного вывода о скорости. Нового валидного ускорения/замедления нет.

Обнаружен дефект контроллера: built-in early stop проверял только block0,
хотя правило требует остановки после первого невалидного блока. После обнаружения
03 остановлен извне; записи сверх первого невалидного блока сохранены и не приняты.
Итоговый `summary.json` не подделывался: CPU audit воспроизводит NO_VERDICT из
`watched.json` и сохраняет `controller-stop.json`. Исправлен только контроллер:
он останавливается после невалидного блока с любым номером; правило, validator,
арифметика и старые записи не изменены. Регрессия проверяет bad block0/1/4 и
полностью валидную сессию; восстановление прежней ошибки вызывает падение теста.
На исправленном head нового CUDA-прогона нет.
Локально: **141 D1/changelog tests passed**, fragment validator, полный Ruff и
diff-check чистые; восстановление block0-only мутации поймано тестом bad block1.
Это не утверждение о полном CI нового head.

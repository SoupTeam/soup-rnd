# H3 conservative BF16: verified training, adapter reload and 1→2 GPU scaling

2026-10-27. **The selected small-model BF16 experiment passed**, with all numeric
references retained and independently checked. Four real training arms and eight
fresh-process root/checkpoint reloads passed. Median input throughput is
**6932.1733 → 7584.7686 tokens/s**; speedup(2) **1.094140**,
efficiency(2) **0.547070**.

This result is explicitly **conservative BF16 with math SDPA and FP32 intermediate
reductions**. It does not validate ordinary Flash/efficient-SDPA BF16, optimizer/
scheduler resume, 4/8 GPUs, 70B or training quality. It completes the requested
BF16 first-stage point within this declared scope, not all H3. The separate
[FP32 report](h3-fsdp-followup-20261027.md) remains valid; its RTX 3090 timings
are not pooled with these RTX 4090 timings.

The later [native Flash BF16 follow-up](h3-flash-bf16-result-20261027.md) passed
with deterministic algorithms and ordinary BF16 GEMM reduction. Default
nondeterministic Flash failed the strict gate and remains diagnostic. Those
timings are separate from this conservative math-SDPA experiment.

## Correctness, data and actual sharding

All microstep losses and inspected gradients are finite. Gradients are inspected
at steps 1, 2 and 18; some are nonzero and frozen base gradients are absent.
The optimizer changes 48 B tensors on step one; unchanged A tensors at LoRA
initialization are allowed. Final adapters change all 96 tensors. Each rank's
frozen-base local hash is unchanged before/after training.

The actual forward observes all 96 LoRA parameters as FP32, CUDA autocast enabled
and all 96 LoRA outputs BF16. The actual backend flags during that forward match
the protocol. FSDP2 reduction is explicitly FP32; parameter/output policy preserves
original dtypes. These are observations, not inferences from requested flags.

Actual accumulation is checked on every step. The first two data windows contain
eight distinct sample hashes each, without duplication across ranks, and match
between worlds/repeats. Reconstructed trainable adapter/reduced-gradient hashes
agree across ranks, including preclip gradients. Different local parameter shards
are not required to equal each other.

Both distributed ranks have 27 public FSDP2 modules and actual
`DTensor.to_local().numel()` readings of **247,286,720 elements/rank**, sum
494,573,440. Per-parameter global shapes/local sizes/placements/dtypes reconstruct
the model without a duplicated tied embedding. The one-GPU arm holds 494,573,440
elements and has zero FSDP units. No global-numel/world-size estimate is used.

The strict per-element first-step criterion remains **atol=1e-5, rtol=0.02**.
All repeats pass against the first one-GPU arm. Maximum absolute first-gradient
error **2.91038304567e-11**; first-updated-adapter error **1.45519152284e-11**. No tolerance
was relaxed after seeing a result.

## Save/reload and evidence retention

Each final adapter and checkpoint-18 reloads in its own new Python process on
the same immutable BF16 base, fixed 1×64-token input, eval mode, matching math
SDPA/AMP. All eight checks retain exactly 96 keys/tensor values and pass the
predeclared output tolerance **atol=1/64, rtol=1/128** (two absolute BF16 ULPs
near one plus one relative ULP). Maximum observed logit error **0**.
Reload PIDs are distinct from training PIDs. This proves adapter reload, not
optimizer/scheduler resume; resume state is not restored in this experiment.

Before training, a random 4 MiB SSH transfer passed byte-count/SHA256 validation.
After each arm and both reloads, its numeric references, adapter saves, configs,
versions and logs were sealed, downloaded and hash-verified locally. A matching
receipt released the next arm, keeping bulk transfer outside training windows.
All four arm archives and the final metadata/data archive survived before the
exact new instance was deleted. Each archive and every member have retained
hashes in the manifest. Public records include init/preclip/first-step tensors
and all eight adapters; larger eval references and prepared data remain in the
five full local archives at the manifest's exact paths.

CPU revalidation exactly reproduces the remote summary and first-step gate,
checks measured source hashes against Git, matches all eight saves to pre-save
references, recalculates throughput from raw rank timings, and checks all six
physical rank records. These are checks of real GPU evidence, not CPU hardware
proof. The original D2 checkout's 129 dirty/untracked snapshot files and HEAD
remain unchanged.

Median throughput(1)=6932.173310; throughput(2)=7584.768596 input tokens/s.
Speedup(N)=throughput(N)/throughput(1); efficiency(N)=speedup(N)/N.
Two pairs are budget-sized repeats, without a narrow confidence-interval claim.
These values describe this BF16/math-SDPA/small-model/global8 host only.

Input tokens/s counts all actual nonpadding input tokens across ranks divided
by the slowest rank's sum of CUDA-synchronized optimizer-step durations. Each
optimizer step is 4096 input tokens (511 causal targets per 512-token sequence).
Step seconds divides that same duration by ten. The window is callback
on_step_begin→on_step_end: forward/backward, rank synchronization, optimizer/
scheduler and intervening callback work. CPU batch fetch before the callback,
initial correctness probes, warmup, loading, eval, checkpoint/final save, archive
traffic and reload are excluded. Compilation is disabled. This is training-loop
compute throughput, not end-to-end job/input-pipeline throughput.

MiB=2^20 bytes. Peaks reset after warmup while the allocator remains warm;
prior correctness gathers may influence reserved memory. Exact bytes and ten
per-rank durations are in raw JSON. RSS/host RAM are sampled every 50 ms and
can miss spikes; summed RSS can double-count shared pages. Host used RAM covers
the system, not just the allocated container. Parameter sharding does not imply
halving total VRAM. No bottleneck attribution or extrapolation is claimed.

stack. See captured bootstrap/continuation for the disposable-image setup;
require `python -m pip check` to pass. On a normal prepared host:

```bash
export PYTHONPATH="$PWD/src" OMP_NUM_THREADS=4 TOKENIZERS_PARALLELISM=false
ROOT=benchmarks/evidence/h3-bf16-replay-20261027
python benchmarks/harness/h3_fsdp_run.py prepare --prepared "$ROOT/prepared" \
  --revision 7ae557604adf67be50417f59c2c2f167def9a775
python benchmarks/harness/h3_fsdp_campaign.py --prepared "$ROOT/prepared" \
  --output "$ROOT/live/campaign" --precision bf16 --bf16-conservative \
  --archive-arms --repeats 2 --measured-steps 10 \
```

external collector; omit that option when retaining archives directly on your

foreign GPU process, insufficient disk, command timeout or cumulative deadline.

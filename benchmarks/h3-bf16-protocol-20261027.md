# H3 conservative BF16 follow-up: protocol fixed before rental

2026-10-27. This is a new experiment; it does not admit the failed earlier BF16
arms. The accepted FP32 result remains in h3-fsdp-followup-20261027.md.

## Hypothesis and arithmetic controls

The saved ordinary BF16 gradients differ across one/two-GPU accumulation.
CPU AdamW replay of each arm agrees with its own saved update within 4.4e-11;
this local replay does not prove GPU correctness or identify the numerical cause.
Try the same BF16 model/AMP with conservative arithmetic: FP32 intermediate
reduction for BF16 GEMM and math SDPA, deterministic algorithms,
CUBLAS_WORKSPACE_CONFIG=:4096:8 and IEEE highest float32 matmul. Force math SDPA
through the public torch.nn.attention.sdpa_kernel context. Check the observed
backend controls during the actual forward, FP32 materialized adapter weights,
CUDA autocast enabled and BF16 LoRA outputs. These controls are benchmark-only;
they do not change Soup defaults or claim to cover ordinary Flash SDPA BF16.

## Frozen experiment and acceptance

Use the model revision, data SHA256, seeds, optimizer, LoRA, global batch eight,
sequence length 512 and schedule in the accepted FP32 report. BF16 base and
compute, FP32 LoRA masters/gradients/reduction in both arms. Use two RTX 3090
GPUs of the same host, with one GPU micro1/GAS8 and two GPUs micro1/GAS4.
Run two alternating pairs (1/2, 2/1), each 2 correctness + 5 warmup + 10 timed
+ 1 final inspection optimizer steps. Exclude setup, first-step instrumentation,
reload, checkpoint/save, warmup and final inspection from training throughput.

Keep the original per-element first-gradient and first-adapter comparison
**atol=1e-5, rtol=0.02**, and stop after the first pair if it fails. Do not change
that criterion using this run's outcomes. Save initial adapter and preclip
gradients as additional diagnostic artifacts. All finite/update/base/data,
rank synchronization and actual DTensor local-shard gates remain required.

Final and checkpoint adapters each reload in separate processes over the same
immutable base. Exact keys/values plus eval output atol=1/64, rtol=1/128 are
required: two absolute BF16 ULPs near one plus one relative ULP, as declared for
the earlier BF16 run. Record actual maximum errors. No optimizer/scheduler
resume claim. Retain raw commands, configs, sources, versions and all reference
tensors before deleting only the newly created instance. A failed criterion
excludes that campaign from measured scaling; preserve diagnostics.

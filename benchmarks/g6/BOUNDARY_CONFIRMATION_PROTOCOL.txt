Question

for the original pinned model and each of the four preserved FULL adapters?
The intervention changes only stopping/scored-answer segmentation. It does not
change prompts, weights, training, template, scorer, token limit or data policies.

Execution
One label per exclusive supervised process; labels in order initial, baseline,
coherence_filter, length_curriculum, reverse_length_curriculum. Each label runs
both diagnostic and confirmation suites under original_v1 and role_boundary_v1.
Even label indices run original then boundary; odd indices reverse that order.
Both use identical literal role render/BOS, greedy decoding, one beam, max128,
EOS and context2048, unchanged strict strip_exact/json_object scorer. Both use
per-token Guard checks. There is no timing or speed recommendation from this test;
no extrapolated GPU budget or full-study performance claim is an observation.

Original mode keeps the whole completion. Candidate mode examines only generated
tokens after each step, decoding the full generated prefix; it stops on the earliest
complete case-sensitive newline user:, assistant: or system:. The raw token that
contains a boundary and any overhang remains stored. Only the scored text ends
before that boundary. Markers in quotations/code also stop: no answer-dependent
exception, no punctuation/case normalization and no substring answer extraction.
For every case save prompt IDs, raw completion IDs/text, scored text, reason,
boundary marker/offset and strict score. Candidate raw IDs must exactly match the
original generation's prefix with identical prompt IDs. Mismatch blocks acceptance.
Safety task_pass remains null and never becomes an automatic pass.

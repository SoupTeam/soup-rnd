# D1 bounded real-7B applicability screen, fixed before CUDA

Purpose: test whether the scoped candidate reduces complete-step peak VRAM on a
real pretrained model through Soup RAM streaming, and check its numerical parity.
This is a short applicability screen, not a new formal F1 or long quality study.
The completed synthetic F1 and all historical rejected cohorts remain unchanged.

Model: mistralai/Mistral-7B-v0.3, revision
`caa1feb0e54d415e2df31207e5f4e273e33509b1`, original safetensors, no remote code.
All 32 layers, hidden4096, intermediate14336, vocab32768, untied embeddings/head.
Soup quantizes decoder weights to nested NF4; BF16, two pageable RAM streaming
slots, q/v LoRA rank4 alpha8 dropout0, standard zero-B initialization, seed842,
SGD lr0.001, one batch of128 naturally tokenized English tokens, causal CE loss.
Text is included in the harness, authored for this screen; no random token IDs.
TF32 off; BF16 reduced-precision reduction remains on. The candidate uses exactly
the existing covered descriptors and shipped fallback everywhere else. No new
kernel arithmetic, descriptor acceptance or reference patches are allowed.

Before timing: repeat the applicable RTX 3090 large recycled-buffer forward/dX
gate with same-process negative control. Then compare three full updates between
fresh native and candidate processes: finite bit-exact logits/loss, every trainable
gradient and updated adapter; record nonzero gradients and candidate dispatch.
Any parity failure stops this screen without timing or attempts to loosen gates.
The prior unpatched-resident synthetic gate is not real-model resident evidence.

If parity passes, run one fresh-process ABBA block,5 warmup and20 synchronized
full SGD steps per arm. Each arm starts from identical adapters/data. Record full
model peaks before the same-session128x4096x4096 dense GEMM, required telemetry,
ArmWatch, peer lifecycle, source/rule/model/settings hashes and actual dispatch.
Use the unchanged <=5% primary/reference clock guard and reference validation.
An invalid block has NO_VERDICT timing; preserve its independent memory/correctness
evidence with contamination limits explicit. Even a clean single block is only a
descriptive quick screen, not five-block F1, sizing acceptance or a speedup claim.
No extra blocks, larger sequences, model swaps or long training in this booking.

Resource limit: one RTX 3090 on the previously clock-capable VM host if available,
exact leased UUID only,1200 MHz, persistence enabled before CUDA and disabled on
cleanup; stop if the requested clock cannot be established. Maximum90 minutes,
new all-in spending <=$1.50 (compute/storage/bandwidth), cumulative D1 <=$15.
Prior visible D1=$8.667; invoices may lag. VM creation, export, exact-ID deletion
and temporary SSH cleanup must be guarded. No unrelated rentals are modified.

Report absolute MiB and percentage of the real full-step baseline; do not transfer
synthetic40% to this model. A small/no saving or failure is a useful negative result.
Successful three-step exactness does not establish long-run training/task quality.

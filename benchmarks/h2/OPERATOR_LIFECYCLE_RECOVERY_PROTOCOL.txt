H2 operator lifecycle recovery v1 — prospective amendment, 2026-10-28

Scope and cause
Attempt010 passed baseline continuity, then failed ce_only before capture:
the diagnostic expected the instance patch after setup. Pinned Transformers
5.17.0 applies that patch in Trainer.train(), which this one-backward diagnostic
deliberately never calls. This explains the harness failure, not the numerical
discrepancy in attempt009. Historical evidence and verdicts remain unchanged.

This amendment supersedes only the instance-patch timing described in
OPERATOR_DIAGNOSTIC_PROTOCOL.txt. All matrix, numerical, identity, runtime,
budget, process ownership, timeout, preservation and stop conditions remain.

Explicit lifecycle
After wrapper.setup and before loaded-model validation or any forward:
1. Require exact trainer.model and model_wrapped identity, declared treatment,
   allowed kernel config, no optimizer or scheduler, step zero, not in train.
2. Require class count one / instance count zero for treatment; both zero for
   baseline. A future dependency applying the instance patch during setup is
   a hard failure, not something silently skipped or applied twice.
3. Treatment invokes the controlled instance patch explicitly with PEFT
   unwrapping and all five flags. Baseline invokes no patch.
4. Retain exact class/instance call counts, global/model/module binding checks
   before and after capture, actual CUDA kernel-family checks and state hashes.
The lifecycle preparation is single-use, including a failed/partial attempt.
HF's intercepted train-time entry point remains guarded against a second patch.
No train(), optimizer creation, optimizer step, retry or threshold change.

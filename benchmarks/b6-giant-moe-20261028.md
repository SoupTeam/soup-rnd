## Disk preparation

`utils/expert_cache_budget.py` reads only bounded safetensors JSON headers,
including FP8. Its narrow budget is for a new NF4 cache on one disk without
nested statistics. It includes conservative dense weights, expert NF4 payload,
metadata, an extra largest layer for temporary writes and a tied-head allowance.
The expert writer validates NF4 output shapes/dtypes/blocksize before writing.
Every atomic shard write separately checks actual payload and free bytes while
preserving an existing destination on refusal. This does not reserve space
against concurrent writers.

Real DeepSeek-V3 header-only plan, revision
`e815299b0bcbac849fa540c768ef21845365c9eb`:

- 163 source files, 688,586,727,753 source bytes.
- 91,991 header tensor entries; 45,312 routed-expert matrices.
- Conservative cache budget: 519,579,082,752 bytes, including reserve.
- This is a calculation, not a measured cache or a RAM-fit result.

## Validation limits

Tiny-model CUDA tests passed on RTX 3070 and RTX 5060 (9 selected GPU cases
on each). These are synthetic correctness checks; the real pilot is running. The small heldout loss probe in `harness/b6_real_moe.py` is not a
general quality benchmark and two updates cannot establish convergence.
The real pilot must log versions, physical GPU and VRAM, RSS, actual disk use,
losses, gradients, adapter updates, speed and reload. A larger-RAM cloud host
cannot establish that preparation fits 32 GB RAM.

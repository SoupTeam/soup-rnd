# D1: рабочий BF16 WMMA-прототип и результат коротких проверок

**Для включения в Soup — NO GO.** Получен fused GPU-кандидат с проверенной
корректностью в явно ограниченном режиме. Штатный режим накопления cuBLAS
не покрыт, подтверждённого ускорения нет. D1 по полной карточке ещё не закрыт.
Этот пакет можно передать тимлиду как воспроизводимый research result.

## Что реализовано

[`d1_wmma_nf4.py`](harness/d1_wmma_nf4.py) распаковывает NF4 непосредственно
в shared-memory плитку CUDA WMMA и вычисляет forward и dX. Полной
промежуточной bf16-матрицы веса нет. Поддержаны обычные и вложенные масштабы;
размеры блоков зафиксированы при компиляции, дорогие деления `div.s64` удалены.
PTX последнего запуска содержит **0 таких делений**.

Явный исследовательский вход:
`d1_fused_nf4.linear(x, packed, state, backend="wmma")`. Он сохраняет все
шесть тензоров NF4 через `save_for_backward`, сохраняет backend для конкретного
autograd-вызова и проверяет владельца streaming-слота. Проверенный режим:
Linux/CUDA sm86, BF16, M >= 128, N кратно 64, K кратно 32, одинаковые dtype
веса и входа. Прототип требует
`torch.backends.cuda.matmul.allow_bf16_reduced_precision_reduction = False`
и отказывает при включённом усечении; самостоятельно глобальную настройку
он не меняет. Первоначальный Triton-кандидат оставлен отдельным экспериментом.
Production dispatch Soup не изменён.

Выполненный оптимизированный исходник:
`ba6928e9af116c11d56257cf8d532ec51c3dee17`.
RTX 3090 24 GB, `GPU-f6a81a9c-198c-c8e5-0be8-91e1deb3b94f`, driver 580.173.02,
Torch 2.11.0+cu126, bitsandbytes 0.50.2. Версии остальных пакетов и точные
исходники выполненных запусков сохранены в пакете.

## Корректность

| Проверка | Результат |
|---|---|
| Предварительные выровненные BF16-проекции: 3 seed × 2 режима scales × 5 форм | 30/30 exact forward и dX; отдельная предыдущая версия WMMA |
| Оптимизированный kernel, packed-буфер 192 MiB, M128/N32768/K12288 | Forward и dX exact относительно native resident NF4 |
| Перезапись packed weights и scales другой моделью перед backward | Checkpoint повторно вызван 2 раза, результаты exact |
| Контроль с хранением буфера вне `save_for_backward` | Ожидаемое отличие dX обнаружено, значения конечны |
| Настоящий streamed Llama decoder, 4 слоя/2 буфера, seq 128 и 2048 | Logits и все 16 наборов LoRA-градиентов exact; resident не патчен |
| Полный синтетический LoRA-шаг с SGD, 3 последовательных обновления | Loss, dX, градиенты и обновлённые A/B exact |

Независимый CPU-аудит сохранённых **CUDA-тензоров** подтвердил большой
буфер и оба decoder-сравнения; LoRA-градиенты ненулевые. Он не заменяет
CUDA-исполнение. Локальные регрессии: **127 passed, 13 hardware skips**,
полный Ruff чистый. Большие сетки и длительный новый тренинг не запускались.

## Почему понадобился отдельный режим накопления

Первые настройки Triton не дали native parity. Профайлер показал WMMA/CUTLASS
у эталона; переход на WMMA устранил исходные расхождения на выровненных
проекциях. Невыровненный N=67 всё ещё расходился, а FP16 не прошёл реальную
MLP-форму. Эти ограничения сохранены, неподдержанные формы новый вход отвергает.

На большом BF16-буфере при обычном разрешённом усечении cuBLAS forward совпал,
**643 663 элемента dX отличались**. При запрещённом усечении и одинаковой
настройке у обоих участников forward/dX совпали. Это отдельный явно объявленный
эксперимент с native bitsandbytes; прежний FAIL сохранён. Смена режима
накопления не объявляется прохождением приёмки с настройками Soup по умолчанию.

## Скорость и память: короткий экран, не итоговый perf-gate

Один синтетический LoRA-блок: M128/N4096/K4096, rank 8, вложенный NF4,
веса уже на GPU. Измерялся полный forward/backward/SGD, три чередующихся
блока по 200 шагов каждого участника. Оба используют полный FP32-режим
BF16-накопления. Это проверка вычислительной части, не тренинг 7B и не NVMe-тест.

| Величина | Native | Оптимизированный WMMA |
|---|---:|---:|
| Наблюдавшаяся медиана полного шага | 2.857 мс | 4.092 мс |
| Пик `memory_allocated` | 119 809 024 B | 95 433 728 B |

Разница пиков — **24 375 296 B, или 23.25 MiB**, на этой форме. Reserved memory
у обоих 146 800 640 B. Наблюдавшееся отношение времени — 1.432; сигнала
ускорения нет. **Формальный вердикт скорости — NO_VERDICT:** SM менялась
от 1545 до 1965 MHz, окна короткие. Сохранены 43 сырых GPU-сэмпла,
utilization памяти, лимит 200 W и отдельный same-session dense GEMM.
Короткий GEMM-интервал также не проходит длительность полного F1-протокола.
Эти числа не добавляются к старой K-сетке.

Предыдущая версия с динамическими делителями дала другой короткий результат
на другой физической RTX 3090: 1.901/5.728 мс native/candidate. Два устройства
и версии не объединяются; сравнение не доказывает величину выигрыша оптимизации.

## Польза для Soup и что осталось

Демонстрирован способ убрать полную bf16-распаковку из forward и dX, сохранив
checkpoint-корректность и снизив пик выделенной памяти в ограниченном режиме.
Это возможный рычаг вместимости. Ускорение Soup, большая допустимая длина
контекста и улучшение реального обучения пока не доказаны.

Для штатного принятия D1 нужно согласовать численный контракт или воспроизвести
обычный режим cuBLAS, затем получить полезную скорость на полном шаге
с валидными частотами. Включение этого кандидата в production сейчас не обосновано.
Новые долгие платные прогоны не планируются этим пакетом.

## Воспроизведение и материалы

На Linux/CUDA с указанными версиями, из чистого checkout выполненного SHA:

```bash
export PYTHONPATH="$PWD/benchmarks/harness:$PWD/src:$PWD"
export CUBLAS_WORKSPACE_CONFIG=:4096:8
export D1_SOURCE_SHA="$(git rev-parse HEAD)"
python benchmarks/harness/d1_wmma_acceptance.py --output /tmp/d1-acceptance-new \
  --diagnose-full-fp32-reduction
# Следующий шаг только при exit code 0 предыдущей команды.
python benchmarks/harness/d1_wmma_step_screen.py --output /tmp/d1-step-new
```

Нужны PyTorch CUDA, bitsandbytes, Transformers 5.17.0, PEFT 0.20.0,
Accelerate 1.14.0, pytest, Pydantic v2 и зависимости Soup. Kernel компилируется
установленным NVRTC. Результаты пишутся только в новый путь.

[Манифест](evidence/d1-wmma-20261016/manifest.json) содержит контрольные суммы
двух полных сырых архивов: журналы, tensor witnesses, исходники, PTX, команды,
пакеты, CUDA-records, включая неудачи. [Аудит](evidence/d1-wmma-20261016/independent-audit.json)
перепроверяет тензоры, source provenance, медианы и отсутствие учётных секретов.
Windows Git archive применил CRLF к Python-файлам; проверено совпадение с
Git blobs после нормализации только концов строк, исходные байты архивов сохранены.

За продолжение этого хода начислено **$0.084**. Все короткие kernel-проверки,
включая прежние $0.023, — **$0.107**. Суммарно D1 **$8.168 из $10**,
остаток **$1.832** по округлённому снимку провайдера. Все созданные D1-машины
удалены, отсутствие проверено; подтверждения лежат в пакете.

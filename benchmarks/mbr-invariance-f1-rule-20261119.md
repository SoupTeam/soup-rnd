# MBR batch-invariance (A2): правило до запуска, F1-цена и таблица исходов

Написано 2026-11-19 до первого GPU-запуска (тикет 06). Метод: `benchmarks/METHOD.md`.
Образец: `benchmarks/p72-f1-rule-20261119.md`. Драйвер F1: `benchmarks/harness/p72_f1_blocks.py`.
План: `.scratch/mbr-batch-invariance/plan.md`.

## Что проверяется

Даёт ли route-preserving MBR (группа 8) побитово те же потерю и градиенты LoRA, что L2L, если
GEMM экспертов не зависит от числа строк (построчный `F.linear`, M=1, `--expert-gemm invariant`) и
градиенты LoRA складываются в том же порядке (`mbr_split_backward`, тикет 03). Модель Moonlight-16B-A3B,
bf16, RTX 3060, окно 8 x 64 токена. S1 на GPU проверяет A2 целиком (GEMM плюс порядок
накопления), не только GEMM.

## Руки (bf16, Moonlight, окно 8 x 64, `--timed-steps 2`)

| Рука | Конфигурация | GEMM |
|---|---|---|
| A0 | complete + L2L + two-read | native |
| A1 | то же | invariant |
| B0 | complete + MBR группа 8 + prefetch | native |
| B1 | то же | invariant |
| O0 (страховка) | ordinary + L2L + two-read | native |

Complete = packed перенос + host cache + grouped routes (термины PR #71); prefetch из PR #74 есть
только в B, на биты не влияет. Так как prefetch у A и B разный, руки запускаются отдельными вызовами
моста (`--expert-transfer`, `--expert-prefetch`, `--expert-host-cache-mib` берутся на уровне вызова,
тикет 03).

## Пары digest (`grad_sha256`, потеря и все градиенты LoRA, без допусков)

| Пара | Ожидание | Роль |
|---|---|---|
| O0 против A0 | равны | страховка: complete ≡ ordinary на Moonlight и RTX 3060 |
| A0 против B0 | различаются (около 10%) | S0, воспроизведение PR #72 |
| **A1 против B1** | **равны** | **гипотеза, S1** |
| B1 при группах 1, 2, 4 против A1 | равны | S2 |
| повтор A1 и B1 | равны | S3, детерминизм (одна пара GPU и версия torch) |
| A0 против A1, A0 против B1, B0 против B1 | различаются, pass/fail нет | справка: размер сдвига эталона (rel-L2, cosine, смены маршрутов, разница потери) |
| B1s (MBR invariant без рычагов, sync) | только если A1 ≠ B1 | разделяет «виноваты рычаги» и «виноват MBR» |

A0 и A1 не обязаны быть равны: native и invariant отличаются самой арифметикой. Invariant это
постоянство, а не обязательно точность (справка: тикет 04).

## F1: цена А2 (B0 против B1)

Запускается **только если S1 прошла**. Третья рука не добавляется. Скорость A1 берётся справкой из
запусков digest-серий, без теста.

- Запуск: свежий процесс моста с `--phase-profile-only --profile-kinds mbr
  --phase-profile-blocks 0 --timed-steps 3`. Число запуска это медиана трёх шагов после разогрева;
  холодный шаг пишется отдельно и в сравнение не входит.
- Порядок A-B-B-A (здесь A = B0, B = B1). Пилот 5 блоков, затем по `blocks_to_add`, не более 10.
- Эффект: парный t-тест по разностям блоков (среднее B1 минус среднее B0), двусторонний, 5%.
- Порог цены: invariant приемлем, если шаг медленнее native не более чем на 10%. Иначе
  рассматривается паддинг M до фиксированного размера (с тестом инвариантности паддинга).
- Строка «grad_sha256 равны между вариантами» не применяется (B0 и B1 различаются арифметикой).
  Вместо неё: **внутри каждого варианта digest повторяется** (B0 с B0, B1 с B1); иначе скорость не
  оценивается.

## Проверки достоверности

| проверка | обязательна | если не выполнена |
|---|---|---|
| `suspend` ok на каждом запуске, который читает вердикт | да | нет вердикта |
| `power` ok на каждом запуске, который читает вердикт | да | нет вердикта |
| `foreign_reads` | нет | см. ниже |

`foreign_reads` исключён из обязательных: на контейнере vast.ai кеш не сопоставляется с блочным
устройством, проверка всегда `unknown`. Чтения соседей по хосту не видны, вывод читать с этой
оговоркой. Void по любой проверке исключает запуск. Запись `gpu_clock` читается вручную по каждому
запуску: медианная частота SM заметно ниже остальных или `sw_power_cap` и `sw_thermal_slowdown` почти
во всех отсчётах означают замену блока.

## Правило запуска: бюджет и остановки (D7)

- Потолок 1,5 USD и не больше 8 ч аренды (оффер около 0,12 USD/ч).
- При 1,0 USD остановиться и спросить пользователя.
- При любой ошибке или непроверенных результатах инстанс не удалять: чинить и перезапускать на нём.
- Для каждого запуска писать `torch.__version__`, имя GPU, хост (`triton.__version__` не пишем, D3).

## Таблица исходов

Факт тикетов 01 и 03 (CPU): склеенная группа и L2L различаются в fp32 и bf16 autocast; построчный GEMM
один равенства не даёт; причины: порядок суммирования градиентов LoRA по микробатчам (fp32) и кэш
весов autocast (bf16). Построчный GEMM плюс `mbr_split_backward` даёт побитовое равенство на CPU
в fp32, bf16 без кэша и bf16 с кэшем. На GPU это проверяет S1.

| Исход | Вывод | Дальше |
|---|---|---|
| S1 равенство есть | гипотеза подтверждена: MBR точен, расхождение это арифметика склейки и порядок накопления | F1 (цена), затем решение о подъёме А2 в `src/`; передача инфраструктуры автору #73 |
| S1 нет, B1 с группой 1 равен A1 | остаточная неинвариантность другого оператора | искать оператор по одному; B1s |
| S1 нет, B1s равен A1 | виноваты рычаги выгрузки (packed, prefetch, host cache) | диагностика рычагов |
| S1 нет, B1s не равен A1 | виноват MBR или другой оператор | `/diagnosing-bugs` |
| S1 нет, S3 (повтор) тоже нет | недетерминизм на самой карте, не A2 | F1 не запускается; детерминизм сначала |
| S1 есть, F1 шаг B1 медленнее B0 более чем на 10% | цена неприемлема для построчного варианта | паддинг M (с тестом инвариантности) или отказ от подъёма |
| CPU красный (факт) | вычислительный источник воспроизводится без GPU | закрыт `mbr_split_backward` плюс построчный GEMM на CPU |

## Границы вывода

Одна модель (Moonlight), одна карта (RTX 3060 12 ГБ), один хост, одно окно, одна версия torch.
Равенство и цена не переносятся на другие GPU и cuBLAS-версии без повтора.

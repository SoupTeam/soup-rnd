# PR #72: куда уходит шаг MBR на Moonlight и что можно выиграть

Дата: 19 ноября 2026 года. Ветка `pr72-diagnostics`, база коммит `312820f8` (route-preserving MBR).

## Вопрос и ответ

Шаг MBR на Moonlight-16B-A3B занимал 17,76 с (RTX 3060 Ti, один запуск, тёплый кеш). На что
уходят секунды, и есть ли узкое место, которое можно убрать на 5–10% и больше?

**Узкое место: чтение экспертов с диска.** На RTX 3060 (хост из таблицы ниже) оно занимает
46% шага (8,6 из 18,7 с). GEMM экспертов занимает 7,7%, из них при малых M (до 32 строк)
3,9%. Это ответ на вопрос про ядро A2: даже бесконечно быстрое ядро для малых M сняло бы
не более 4% шага, на нём работать не стоит.

Выигрыш нашёлся в передаче и чтении, а не в вычислениях. Все сравнения ниже в блоках
A-B-B-A, градиенты побитово равны во всех вариантах.

| Что включено | Шаг, с | Против обычного `sync` | Серия |
|---|---:|---:|---|
| `sync` (по умолчанию) | 18,6–20,2 | база | |
| `packed` (одна копия хост→GPU) | 17,4 | около −6% (в 3 блоках −6,4/−5,9/−6,1%) | `sync` против `packed` |
| `packed` + предзагрузка эксперта | 16,6 | около −11% к `packed` (−10,9/−11,0/−10,9%) | `packed` против предзагрузки |
| `packed` + хост-кеш 12 ГиБ | 7,4 | −60% к `packed` (−59,3/−60,3/−60,0%) | `packed` против кеша |
| `packed` + предзагрузка + хост-кеш | 7,4 | **−63,1%** (F1, 5 блоков, t = −124) | `sync` против всего вместе |

Хост-кеш (`--expert-host-cache-mib`) уже был в коде. Предзагрузка (`expert_prefetch`) добавлена
этой веткой, по умолчанию выключена.

## Разбивка шага MBR по фазам

RTX 3060 12 ГБ, EPYC 7402, группа 8, `sync`, шаг 18,68 с с инструментацией (замер без неё
17,9–19,3 с). Все три условия профайлера выполнены: |шаг − сумма фаз| 0,00%, неучтённое 0,5%,
градиенты побитово равны.

| Фаза | Секунды | Доля |
|---|---:|---:|
| Чтение эксперта с диска | 8,57 | 45,9% |
| Копия хост→GPU и сопутствующее | 2,39 | 12,8% |
| Backward autograd без экспертов | 1,91 | 10,2% |
| Attention, роутер, shared-эксперты (forward + backward) | 2,32 | 12,4% |
| GEMM экспертов (forward + backward) | 1,44 | 7,7% |
| Деквантизация NF4 | 0,64 | 3,4% |
| Загрузка весов слоёв | 0,46 | 2,5% |
| Диспетчеризация экспертов | 0,68 | 3,7% |
| Прочее (синхронизация, склейка, хранилище активаций, неучтённое) | 0,28 | 1,5% |

Оптимизатор в этот шаг не входит (`L2LStep.run` его не вызывает).

GEMM экспертов по числу строк M на вызов, за шаг:

| M на вызов | вызовов | секунд | доля шага |
|---|---:|---:|---:|
| до 8 (в среднем 4) | 302 + 302 | 0,27 | 1,4% |
| до 32 (в среднем 20) | 546 + 546 | 0,47 | 2,5% |
| до 128 (в среднем 58) | 585 + 585 | 0,52 | 2,8% |
| до 512 (в среднем 241) | 140 + 140 | 0,18 | 1,0% |

Диск подтверждён счётчиками процесса: за шаг прочитано 15,1 ГиБ из хранилища при 14,3 ГиБ
логических. Чтения идут напрямую (O_DIRECT), кеш страниц их не обслуживает. Каждый
эксперт читается дважды за шаг (forward и backward).

## Что изменено в коде

1. **Предзагрузка эксперта** (`expert_stream.py`, `layer_stream_runtime.py`,
   `expert_transfer.py`): один рабочий поток читает следующего эксперта слоя во второй
   хост-буфер, пока считается текущий. В forward подсказывается следующий эксперт, в backward
   предыдущий. Подсказок через границу слоёв нет. Чужая подсказка отбрасывается, ошибка
   фонового чтения поднимается в нужной аренде, одно чтение в полёте на весь пул. API-флаг
   `expert_prefetch`, в конфиге и CLI его нет. Попадание фонового чтения около 98% (52
   промаха на шаг: первый эксперт каждого слоя в forward и в backward).
2. **Измерительный код** (`benchmarks/harness/p72_*.py`): профайлер фаз, драйвер F1-блоков,
   подготовка кеша Moonlight. В `p3_route_preserving_mbr_soup_bridge.py` добавлены
   `--phase-profile`, `--phase-profile-only`, `--profile-kinds`, `--timed-steps`,
   `--expert-prefetch`. Мост был несовместим с PR #72 (хуки на экспертах отвергаются валидатором,
   `InstrumentedL2LStep` не принимал `deferred_hooks`), для профиля он обходит оба места.

## F1-проверка итогового сравнения

Правило решения записано до запуска: `benchmarks/p72-f1-rule-20261119.md`. 5 блоков по 4 запуска,
каждый запуск в новом процессе под `ArmWatch`, число запуска это медиана трёх шагов.

- `suspend` и `power` `ok` на всех 20 запусках, void нет. `foreign_reads` всегда `unknown`
  (каталог кеша на контейнере не сопоставляется с блочным устройством), в обязательные не входил,
  причина указана в правиле. Чтения соседей по хосту этим прогоном не видны.
- Частота SM: медиана 1777 МГц на всех запусках, причины троттлинга только `gpu_idle`.
- σ = 0,185 с, по формуле F1 нужно 2 блока, пилота из 5 хватило.
- Контрольная сумма градиентов одинакова во всех 20 запусках.

Исходные данные: `benchmarks/results/p72-diagnostics/` (`f1_report.json` с записью каждого
запуска, `series_summary.json` со всеми сериями, профили фаз, окружение хоста).

## Границы вывода

- Одна модель, одна карта, один тип хоста, одно фиксированное окно 8 × 64 токена.
- Хост-кеш заполняется на разогревочном шаге, измерение идёт на заполненном кеше, и он вмещает
  весь набор экспертов Moonlight (9,3 ГБ). Для моделей, где эксперты не помещаются в RAM,
  −63% не переносится. Там надёжный выигрыш дают `packed` (около −6%) и предзагрузка (около
  −11%), а предзагрузка пока скрывает только часть чтения: чтение эксперта (около 3 мс) длиннее
  вычисления, за которым оно прячется.
- Первые прогоны на хосте с другим диском дали шаг 10,4 с вместо 18,6 с при той же карте.
  Доля диска зависит от хоста, цифры выше не переносятся на другой диск без повторного замера.
- Серии `sync`/`packed` и `packed`/хост-кеш шли без `ArmWatch` и без записи контрольной суммы
  градиентов. Их выводы подтверждены только итоговой F1-серией, где равенство градиентов
  проверено для `sync` и для комбинации «всё вместе».
- Ранний профиль на другом хосте (RTX 3060, Юта) считал чтения с диска и копию хост→GPU
  неверно из-за ошибки профайлера (кадры рабочего потока autograd отбрасывались). Он исправлен,
  в этот отчёт и в результаты он не входит.
- Полный прогон тестов не выполнялся: проверены новые тесты и существующие тесты по стримингу и L2L.

## Как повторить

CPU, секунды (микромодель): `PYTHONPATH=$PWD/src:$PWD python benchmarks/harness/p72_mbr_phase_profile.py
--storage nf4`. С флагом `--coarse` команда обязана завершиться кодом 1.

GPU: подготовить кеш `p72_prepare_moonlight_cache.py --root /workspace/p3-baseline`, затем
`p72_f1_blocks.py --root /workspace/p3-baseline --output results/f1` (после этого `f1_report.json`).
